• Чтобы проверить состояние файлов в ветке необходимо ввести:
$git status
• Чтобы просмотреть конкретные изменения в файлах необходимо ввести:
$git diff
• Чтобы создать новую ветку необходимо ввести:
$git branch "имя ветки"
* создаёт новую ветку но не переходит в неё.
$git checkout -b "имя ветки"
* создаёт новую ветку и переходит в неё.
• Чтобы посмотреть на какой ветке ты находишься необходимо ввести:
$git branch
• Чтобы отправить новую ветку на сервер необходимо ввести:
$git push -u origin "имя ветки"
* Флаг -u связывает локальную ветку с одноимённой на сервере (upstream),
  чтобы потом можно было просто писать git push без параметров.
• Если на удалённом репозитории, в определённой ветке появились изменения после, 
условной, старой версии, с которой ты также работал и сделал свои изменения;
Чтобы загрузить эти изменения в свою директорию, используй:
$git fetch
* Это создаёт новую ветку в твоём репозитории с аналогичным названием ветки,
  с отличием в том, что одна будет "local/"имя ветки", 
  а вторая "remote/"имя ветки".
• Чтобы посмотреть информацию о коммитах необходимо ввести:
$git log
• Чтобы посмотреть изменения в файле построчно, узнать кем они были сделаны, 
когда, и какое сообщение коммита было, необходимо ввести:
$git blame
* ВАЖНО! Неизвестно до конца как этим пользоваться - необходимо разобраться,
  узнать и дополнить гайд.
• Команда совмещающая функции fetch и merge. Что использовать её, 
необходимо ввести:
$git pull
• Команда позволяющая обратить изменения любого коммита. Что использовать её, 
необходимо ввести:
$git revert
* При этом, действие этой команды создаёт свой коммит - коммит удаления изменений.
• Команда, позволяющая выборочно взять один коммит (как правило из другой ветки). 
Что использовать её, необходимо ввести:
$git cherry-pick
* Полезно для того чтобы взять необходимое для твоей работы изменение и например 
  не делать merge, когда ветки ещё не готовы для объединения.
• Чтобы посмотреть информацию о последнем коммите необходимо ввести:
$git show
